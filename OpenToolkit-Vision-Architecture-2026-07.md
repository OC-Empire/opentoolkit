# OpenToolkit Vision Architecture (2026-07)

## Product Thesis

OpenToolkit is not a directory of apps.

It is a software intelligence and stack-design platform for people trying to replace weak defaults with deliberate, higher-trust digital systems.

Core jobs:

1. Help people discover better software.
2. Help people compare serious options.
3. Help people migrate away from sticky incumbents.
4. Help people compose full stacks around outcomes.

## Positioning Shift

Old mental model:
- homepage
- searchable catalog
- fixed-count tool list

New mental model:
- discovery engine
- compare engine
- migration engine
- stack builder
- editorial trust layer

## Product Surfaces

### 1. Home
- manifesto
- fast-entry paths
- live discovery layer
- top-pick signal board
- compare previews
- migration previews
- editorial collections

### 2. Tool Dossiers
- why it matters
- best for
- alternatives
- complements
- stack membership
- trust and source details

### 3. Compare
- opinionated head-to-head guides
- explicit tradeoffs
- winner-for statements
- link-through to dossiers

### 4. Migrations
- replacement journeys
- pain-level framing
- staged transition logic
- recommended replacement sets

### 5. Stacks
- outcome-driven bundles
- audience fit
- setup logic
- linked tool graph

## Design Principles

1. Outcome-first, not category-first.
2. Opinionated without becoming arbitrary.
3. Visual drama must support clarity.
4. Every surface should make a decision easier.
5. The site should feel alive, not archived.
